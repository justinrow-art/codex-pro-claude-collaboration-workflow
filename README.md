# GPT-6 Luna 協調的 Pro × Claude Code × Agent Teams 計畫審查流程

[English](README.en.md)

這個流程把 **Codex（GPT-6 Luna）定位為低成本的訊息協調者**：它接收使用者需求，把問題送到側欄的 Pro 網頁對話（模型介面顯示 GPT-6），再把計畫交給 Claude Code 和 Agent Teams 交叉檢核，最後把意見帶回 Pro 修訂。

Luna 的主要工作是傳遞訊息、管理討論上限、整理意見和保留紀錄；計畫由 Pro 提出，審查由 Claude Code 與 Agent Teams 負責。這樣設計是為了降低只由同一模型擬定並自我審查時，可能延續相同假設或盲點的風險。使用較低成本的模型承擔協調工作，是成本控制目標；本文件不宣稱已量測實際節省金額。

> 初稿：這是流程文件與範本，不是已驗證的 API 串接或自動化產品。側欄操作、模型標籤、Agent Teams 的實際模型和呼叫上限，都要依當次介面與工具狀態核對。

## 一個完整循環

1. 使用者把目標、限制和驗收條件交給 Codex 協調者。
2. GPT-6 Luna 將凍結的需求送到側欄 Pro 對話，由 Pro 建立或修訂計畫。
3. Claude Code 針對計畫找出漏洞、缺漏、反例與待查證事項。
4. Agent Teams 進一步討論計畫與審查意見；可取得的成員觀點和團隊結論分開記錄。
5. Luna 整理問題清單並送回 Pro，要求逐項回應及修訂。
6. 按事先設定的循環上限重複；上限到達時，若仍有未解決項目，就標示待決或阻塞，不宣稱零錯誤。

## 角色分工

| 角色 | 工作 |
| --- | --- |
| 使用者／決策者 | 定義需求、範圍、驗收條件，並決定是否授權執行。 |
| Codex（GPT-6 Luna） | 傳遞訊息、凍結材料、管理循環與請求計數、記錄意見和狀態。 |
| 側欄 Pro（模型標示 GPT-6） | 建立初始計畫，並根據審查意見逐項回應、修訂。 |
| Claude Code | 對計畫做交叉檢核，指出風險、缺漏、錯誤假設和驗證需求。 |
| Agent Teams | 從多個代理角度討論計畫和審查意見；實際成員、模型與呼叫數依工具顯示記錄。 |

## 重要界線

- 預先設定「完整討論循環上限」和「模型請求上限」；Agent Teams 內部呼叫若可見，也逐次計數。若工具無法揭露內部呼叫數，就標示計數限制，不假稱完全掌握。
- 不同工具不必然代表統計上獨立的模型；記錄看得到的模型與設定，不把多數意見當成事實證明。
- Pro、Claude Code 或 Agent Teams 沒有讀到完整材料時，該次審查不算完成。
- 有限次討論只能表示完成了指定檢核，不代表計畫沒有錯誤。保留分歧、未知項和未通過的驗收條件。
- 計畫審查與計畫執行分開；執行要有明確授權並留下驗收證據。
- 公開前要人工檢查內容，並用本機工具掃描目前檔案和完整 Git 歷史。若憑證可能已公開，先撤銷或輪替；掃描無命中不等於零風險。
