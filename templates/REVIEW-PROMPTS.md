# 計畫審查提示詞範本

[English](REVIEW-PROMPTS.en.md)

每次請求記錄提示詞版本和輸入雜湊。所有審查角色應收到同一版凍結材料；若有省略或截斷，明確標示。

## A. 側欄 Pro：建立或修訂計畫

你負責提出或修訂計畫。只根據實際讀到的材料作答，區分來源支持的事實、推論和未知項。不要執行計畫、修改檔案或聯絡他人。

**需求與目標：** [內容]

**允許範圍／排除事項：** [內容]

**驗收條件：** [內容]

**凍結材料與版本：** [貼上或指明精確版本和 SHA-256]

請列出步驟、理由、依據、假設、風險、未知項、待驗收事項，以及最需要外部審查者挑戰的主張。

## B. Claude Code：交叉檢核

請以對抗性審查角度檢查計畫。不要因為另一模型提出計畫就假設它正確，也不要為了找錯而否定有依據的內容。只審查實際讀到的材料；不要執行程式、修改檔案或呼叫外部服務。

**需求與凍結材料版本：** [同一版材料與雜湊]

**Pro 計畫：** [全文；標示版本]

請回覆實際讀到的內容、有無材料缺漏；逐項列出支持／反對／證據不足、具體理由、反例、失效條件和必要驗證。材料不完整或版本不符時直接回報，不要自行補齊。

## C. Agent Teams：多代理討論

請討論此計畫並找出可能的錯誤、遺漏與未知項。先保留各代理可辨識的個別觀點，再形成團隊摘要。不要執行計畫或修改材料。

**凍結材料版本：** [同一版材料與雜湊]

**Pro 計畫：** [全文與版本]

**Claude Code 審查：** [全文；如有截斷請標示]

請逐項標明代理角色／可見模型、意見、依據、反例、分歧和需要外部驗證的主張。若工具不顯示成員模型或內部呼叫數，標為 UNKNOWN，不要推定。

## D. Pro：處理交叉審查意見

請逐項回應 Claude Code 與 Agent Teams 提出的意見。對每一項標示採納、部分採納、拒絕或未知，並說明依據、計畫如何變更和仍存的不確定性。

**原計畫版本：** [版本與雜湊]

**Claude Code 意見：** [全文]

**Agent Teams 意見：** [個別意見和團隊摘要]

最後提供修訂計畫、未解決清單、尚未通過的驗收條件，以及建議狀態。不要宣稱零錯誤、已執行或已驗證。
